# Workstation Meva Online — Windows Setup Guide (Windows 10 / 11)

Step-by-step instructions for running the **Workstation Meva Online** server on a **Windows 10 or Windows 11** PC, making it available to every user on the office LAN, and optionally auto-starting it at boot. Includes the **standalone .exe installer** (recommended), the **one-click launcher**, and a fully **manual setup** path.

This version uses **your own Supabase PostgreSQL database** (free tier) instead of a local database file — every fresh install starts with an empty database and the first user to sign up becomes the admin.

## 2. Quick Install (.exe Installer)

> **Beta:** this is a pre-release beta (`v1.0.0-beta.1`) running in **testing mode**, and the
> app is **free & public domain (Unlicense)**. The installer **never carries over user data** —
> it always deploys a fresh copy (no database, no settings), ready for new users only.

The easiest path: double-click a single `.exe` file and the app is installed with Start Menu shortcuts, a desktop shortcut, firewall rule, and Add/Remove Programs entry.

### What it does

- Copies the pre-built application (frontend + backend + bundled Node.js + Caddy) to `C:\Workstation-Meva`
- Ships a **fresh copy only** — database files, `.db`/`.sqlite`, `.env`, logs, backups, and telemetry are explicitly excluded, so no previous user data ever ships
- Creates a `.env` configuration file on first launch (random JWT_SECRET generated by the launcher)
- Opens port 3002 in the Windows Firewall
- Creates Start Menu shortcuts (Start, Stop, **Control Panel**, Autostart, Uninstall)
- Creates desktop shortcuts (**Workstation Meva**, **Workstation Meva Control Panel**)
- Registers in Add/Remove Programs
- Asks you to **accept the Terms and Conditions** before installing (the wizard blocks "Next" until you tick the box)
- If the app is **already installed**, the wizard shows a single **Maintenance** page instead of separate Modify/Repair options — **Reinstall / Repair** (refresh all files, keeps your data) or **Uninstall**
- Opens the **Control Panel** when done — the one place to set up your database, start the server, and open the app

### Control Panel

The Control Panel (`windows\Control Panel.bat` → `Control Panel.ps1`, or the desktop/Start Menu shortcut) is the launch pad for first-time setup and daily use:

- **Server** — live status (running/stopped, port 3002, health, PID/uptime) with **Start / Stop / Open app**
- **Autostart at login** — one-click On/Off toggle (same Startup-folder shortcut as `Install Autostart.bat`)
- **Proxy (Caddy)** — status on port 80 with Start/Stop, plus `http://<LAN-IP>` / `http://<hostname>` quick-copy buttons
- **Database (Supabase)** — reads `DATABASE_URL` from `backend\.env`; if empty it shows a **"Set up your database first"** banner, a paste-the-URL box with **Save**, and a **Test now** live connectivity check. (Set up the database before creating your first account!)
- **Reach this computer** — local / LAN / hostname URLs with copy buttons
- **Tools** — Repair launcher, Heal firewall rule, Clean junk files, View `server.log`, Open backend folder
- **Settings** — "open the app in a browser after starting" toggle, port display, version/about (public domain)

The panel reads and writes the **same** state files the `.bat` launchers use — nothing is duplicated or broken by it.

### Install

1. Run `installer\workstation-meva-setup.exe`
2. Click **Next** on the Welcome page
3. Tick **"I accept the Terms and Conditions"** and click **Next** (the wizard will not continue without it)
4. Choose the install folder (default: `C:\Workstation-Meva`)
5. Click **Install**
6. When finished, the **Control Panel opens** — paste your Supabase connection string into the Database card and click **Save** (or follow the guide), then click **Start** and **Open app**

The app opens at `http://localhost:3002`. Create your first account — it becomes the **admin**.

### Re-run the installer (Maintenance)

If the app is already installed, re-running `workstation-meva-setup.exe` shows a single **Maintenance** page (there is no separate Modify / Repair step anymore):

- **Reinstall / Repair** (default) — refreshes ALL application files, shortcuts and the firewall rule; your data in the install folder is kept
- **Uninstall** — removes Workstation Meva Online from this computer (see below)

Choose one and click **Next**.

### Uninstall

- Open **Add/Remove Programs** → **Workstation Meva Online** → **Uninstall**
- Or use the Start Menu shortcut: **Workstation Meva → Uninstall**
- Or re-run the installer and choose **Uninstall** on the Maintenance page

When you start the uninstaller you are asked what to remove:

- **Keep user data** (default) — removes the program but keeps your local data: `workstation.db`, backups, telemetry, `server.log`, `backend\.env`
- **Remove ALL data** — cleans the entire install folder, including all local databases, logs and settings

> Your **online** data always stays safe in your Supabase database either way — these choices only affect files stored locally.

The uninstaller then stops the server, removes the firewall rule, shortcuts and registry entries, deletes the chosen files (or the whole folder), and finally removes `Uninstall.exe` and the install directory itself.

### Rebuild the installer

If you need to rebuild the installer after code changes:

```
cd frontend && npm run build
cd ..\backend && npm run build
cd ..
"C:\Program Files (x86)\NSIS\Bin\makensis.exe" installer\workstation-meva-setup.nsi
```

The NSIS script is at `installer\workstation-meva-setup.nsi`. NSIS (Nullsoft Scriptable Install System) must be installed (`winget install NSIS.NSIS`).

## 3. One-Click Launcher (from source)

This is the easiest and recommended path. It handles everything automatically.

### Step 1 — Install Node.js

Run the bundled offline installer **once** (you will not need to do this again):

```
tools\node\node-v24.19.0-x64.msi
```

Or download from https://nodejs.org (any version 18+).

Open **Command Prompt** and confirm:

```
node --version
```

You should see `v18.x.x` or later.

### Step 2 — Clone the Repository

Open **Command Prompt** and run:

```
git clone https://github.com/kuldeep7ke/workstationmeva-setup.git
cd workstation
```

If **Git** is not installed: download from https://git-scm.com/download/win (default options are fine, enable "Git Bash").

### Step 3 — Set up and start (Control Panel, recommended)

There are two ways to start the app:

- **Control Panel (recommended):** `windows\Control Panel.bat` — the same native panel
  you get from the installer. Use it to paste your **database URL** (Database card →
  Save → Test now), toggle **autostart** and the **proxy**, see LAN addresses, and hit **Start**.
- **Direct launcher:** `windows\Start Server.bat`

Both work identically from a source checkout. The launcher (used by the panel's Start button too) does everything:

- Creates `backend/.env` automatically (random `JWT_SECRET`, local database until you connect Supabase)
- Installs backend and frontend dependencies if missing
- Builds backend (`tsc`) and frontend (`vite build`) if dist folders are missing
- Starts the server hidden in the background (auto-restart wrapper handles crashes)
- Heals the Windows firewall rule (TCP 3002, all network profiles)
- Opens the app in your default browser when ready

> **First build takes 10–30 seconds.** After the browser opens, create your first account — it automatically becomes the **admin**.

### Connect Supabase (optional, recommended)

To use a real database instead of the local SQLite file:

1. Open **Backups → Database** tab in the app (admin only)
2. Paste your Supabase connection string and click **Connect**
3. Choose **Fresh Start** (pushes local data) or **Restore** (pulls online data)

Alternatively, edit `backend/.env` directly (see [Section 4](#4-configure-the-database-supabase)).

### Double-click again while running?

The launcher detects the server is already up and just opens the browser — nothing bad happens.

## 5. Configure the Database (Supabase)

**Before connecting Supabase:** make sure you have already created the schema by running the server at least once (Step 2 or Step 3 above). The server auto-creates all 30 tables on first start.

**Full instructions:** see **[SETUP-SUPABASE.md](SETUP-SUPABASE.md)**.

**Quick version:**

1. Open https://supabase.com → **New project** (free)
2. Choose a region near you, set a database password
3. Open **Project Settings → Database → Connection string** → select **Pooler** (port 6543)
4. Copy the connection string

**Paste into the app:**

1. Sign in as admin
2. Go to **Backups → Database**
3. Paste the connection string, click **Connect**
4. Choose **Fresh Start** (push local data to Supabase) or **Restore** (pull online data)

**Or paste directly into `backend\.env`:**

```
DATABASE_URL=postgresql://postgres.PROJECT:PASSWORD@aws-0-REGION.pooler.supabase.com:6543/postgres
```

> ⚠️ URL-encode special characters in the password: `&` → `%26`, `%` → `%25`, `@` → `%40`

Then restart the server.

## 6. LAN Access for Other Machines

By default, the firewall rule is created automatically by `Start Server.bat`. Other machines on the same network can open:

```
http://<SERVER-IP>:3002
```

### Find the server's IP

Open Command Prompt on the server PC:

```
ipconfig
```

Look for "IPv4 Address" under the active Wi-Fi or Ethernet adapter (typically `192.168.x.x`).

### If the firewall rule is missing

The launcher auto-heals it. To add it manually:

```
netsh advfirewall firewall add rule name="Workstation Meva 3002" protocol=TCP dir=in localport=3002 action=allow profile=any
```

### Access via computer name (no IP needed)

On each client PC, double-click:

```
lan\Add Workstation Hosts.bat
```

After that, everyone can open:

```
http://workstation:3002
```

> **How it works:** the script adds an entry to the Windows `hosts` file mapping
> `workstation` to the server's current IP. Run it again if the server IP changes.

> **For Mac/Linux clients:** run `lan/Add Workstation Hosts.command` in Terminal (requires sudo for the hosts file).

## 8. Reverse Proxy (Caddy — Access Without :3002)

Caddy is an optional reverse proxy that serves the app on **port 80**, so LAN users can open:

```
http://<SERVER-IP>        (no :3002 needed)
```

The Caddy binary is bundled (`proxy\caddy\caddy.exe`) and starts automatically with `Start Server.bat` if the file exists.

### Install Caddy manually

Download from https://caddyserver.com/download (Windows amd64) and place it as `proxy\caddy\caddy.exe`. Start the server again — it will auto-detect and start Caddy.

### Caddyfile

The bundled configuration (`proxy\caddy\Caddyfile`):

```
:80 {
  reverse_proxy 127.0.0.1:3002
  encode gzip zstd
  header Connection upgrade
}
```

You can edit this file to serve on a different port or add a domain name.

### Stop Caddy manually

```
taskkill /f /im caddy.exe
```

Caddy is always stopped automatically when `Stop Server.bat` runs.

## 12. Building the Installer

The installer is a single-file NSIS build that bundles the **pre-built app** plus a portable Node.js runtime and Caddy — the target machine needs no Node/npm/git/internet.

### Prerequisites

- **NSIS 3.x** installed: `winget install NSIS.NSIS`
- The app must be built at least once (`npm run build` in both `frontend` and `backend`)
- The portable Node.js zip must be extracted once: `tools\node\node-v24.19.0-win-x64\` (bundled in the repo as a zip)

### Steps

```
cd frontend && npm run build
cd ..\backend && npm run build
cd ..
"C:\Program Files (x86)\NSIS\Bin\makensis.exe" installer\workstation-meva-setup.nsi
```

Output: `installer\workstation-meva-setup.exe` (~68 MB).

### What gets bundled

| Source | Installed to |
|--------|--------------|
| `frontend\dist\` | `$INSTDIR\frontend\dist\` |
| `backend\dist\` + `backend\node_modules\` | `$INSTDIR\backend\` |
| `tools\node\node-v24.19.0-win-x64\` | `$INSTDIR\node\` (portable Node.js) |
| `proxy\caddy\caddy.exe` + `Caddyfile` | `$INSTDIR\proxy\caddy\` |
| `windows\` launcher scripts | `$INSTDIR\windows\` |
| `lan\Add Workstation Hosts.bat` | `$INSTDIR\lan\` |
| `app.installed` marker | `$INSTDIR\app.installed` — tells the launcher this is a pre-built (packaged) layout, so **Start never runs `npm install`/builds** (works fully offline). Without it, start could fail right after the proxy starts — the "Caddy runs but the server never starts" bug |

The installed server detects and uses the bundled Node.js automatically (`windows\start-server-core.ps1` prepends `$INSTDIR\node` to PATH when present) — no separate Node installation required.

## 13. Launcher Internals

The self-healing launcher (`windows\start-server.ps1`) runs these steps in order on every start:

1. **Self-repair** — compares `Start Server.bat`, `Stop Server.bat`, `Start Server Hidden.vbs`, and `firewall-heal.bat` against known-good content; restores any that are missing or corrupted
2. **Already running?** — checks via HTTP (not just port open); if the server is up, just opens the browser
3. **Junk cleanup** — deletes log files and tsbuildinfo older than 7 days
4. **Firewall self-heal** — adds the TCP 3002 rule if missing
5. **Caddy auto-start** — starts Caddy if `proxy\caddy\caddy.exe` exists and is not already running
6. **`.env` auto-create** — from `backend\.env.example`, generates a random 64-hex JWT_SECRET
7. **Dependencies and build** — `npm ci` when `node_modules` is missing; `npm run build` when `dist` is missing
8. **Auto-restart wrapper** — `start-server-core.ps1` spawns and monitors `node dist\index.js`; restarts after crash, max 5 in 60 s, then gives up
9. **Wait and open browser** (visible/open modes) — polls `http://localhost:3002/api/health` up to 60 s, then opens the browser

**Manual repair:** `windows\Repair Launcher.bat` forces a repair of all launcher files and exits without starting anything.

**Clean Junk.bat** deletes logs and build caches older than 7 days.

**Create .env.bat** creates a fresh `backend/.env` from the example template.

## 14. Troubleshooting

| Symptom | Likely Cause | Fix |
|---------|-------------|-----|
| `node is not recognized` | Node.js not installed or not in PATH | Install from `tools\node\node-v24.19.0-x64.msi` or https://nodejs.org; restart the command prompt |
| `Start Server.bat` closes instantly with no browser | cmd quoting bug — file corrupted | Run `windows\Repair Launcher.bat`, or re-download `Start Server.bat` from the repo |
| Server starts but LAN users cannot reach it | Windows firewall blocking port 3002 | `netsh advfirewall firewall add rule name="Workstation Meva 3002" protocol=TCP dir=in localport=3002 action=allow profile=any` — or let the launcher auto-heal it |
| "Cannot GET /" in browser | Frontend not built (dist folder missing) | Run `cd frontend && npm run build`; or just restart with `Start Server.bat` which builds automatically |
| "Cannot GET /" persists after build | Old server process still running | Stop all node processes and restart: `taskkill /f /im node.exe`; wait 10 s; start again |
| Server crashes on start | `.env` missing or malformed | Run `Create .env.bat` or let `Start Server.bat` create it; check `server.log` for details |
| `npm ERR!` during install | Corrupted `node_modules` | Delete `node_modules` in both `backend` and `frontend`; run `npm ci` again in each |
| "Port 3002 already in use" | Stale server or another app on 3002 | `taskkill /f /im node.exe`; or change port in `backend\.env` (`PORT=3003`) and restart |
| No sound from firewall prompt | Firewall add requires elevation | Run Command Prompt as Administrator, then the `netsh` command |
| LAN users see "workstation" not resolved | Hosts file not updated | Run `lan\Add Workstation Hosts.bat` on the client PC |
| Autostart runs but no browser opens | Designed behavior — autostart is hidden | Open browser manually to `http://localhost:3002`; the autostart does not open a browser |
| `Start Server.bat` says "repairing" repeatedly | `Normalize-Content` mismatch (whitespace/encoding) | Open `Start Server.bat` in Notepad and save with UTF-8 (no BOM), or let the launcher repair itself |
